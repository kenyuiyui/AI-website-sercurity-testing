這個工具查得到什麼、查不到什麼

使用前先看這頁，避免對掃描結果有錯誤期待。「工具沒標記」不代表「沒問題」。

查得到
  • 已知格式的明文 API 金鑰（OpenAI／Anthropic／Gemini／Firebase／Line／AWS）
  • Supabase／JWT 金鑰，並區分 anon（可公開）與 service_role（絕不可公開）
  • 密碼是否用 MD5／SHA1 這類弱雜湊（含 Python hashlib.new('md5') 兩段式寫法）
  • HTML／框架設定檔是否設定 Content Security Policy
  • SQL Injection（字串拼接、模板插值、f-string、Python % 格式化）
  • 不安全的反序列化／動態執行（eval、exec、pickle、yaml.load）
  • 疑似缺少擁有權驗證（IDOR），含 Express 路由寫法
  • 多檔案模式：同一敏感欄位在不同檔案的遮罩不一致、路由缺少速率限制
做不到／僅供保守提示
  • 字串拆分組合而成的金鑰
  • 協定層級漏洞、需動態執行才能確認的邏輯漏洞
  • IDOR 只是模式比對，主要針對 JavaScript／Express；不保證抓到，也一定會有誤判
  • 疑似自訂密鑰、內部端點 URL、環境變數明文 fallback — 沒有固定格式，誤判率較高
  • .env 需直接貼上文字內容；工具不會讀取你的檔案系統（拖入的檔案也只在瀏覽器內讀取）
  • 後端是否真的驗證了前端送出的密鑰／權杖 — 工具只看得到你貼上的這份程式碼
  • 雲端 IAM 權限設定

「建議複查」的意思只是「這裡看起來可疑」，需要自行對照程式邏輯確認，不是漏洞確診。規則主要針對 JavaScript／TypeScript／Python 常見寫法設計，其他語言涵蓋有限，掃描後會依貼上內容的語言特徵提示。

怎麼拿到「要貼進去的內容」

瀏覽器的安全機制不允許網頁擅自讀取別的網站內容，所以需要你先把內容複製出來（或把檔案拖進掃描框）。以下方法任選一種：

方法一檔案就在你的電腦上
  1. 直接把檔案拖進掃描框，或按掃描框右上角的「開啟檔案」
  2. 有好幾個檔案（例如前端、後端分開）時，先勾選「多檔案模式」再一次拖入
方法二網站已經上線，但手邊沒有原始檔
  1. 打開你想檢查的網頁
  2. 在頁面空白處按右鍵，選「檢視網頁原始碼」（View Page Source）；或在網址前加上 view-source:
  3. 按 Ctrl+A（Mac：Cmd+A）全選，再按 Ctrl+C（Mac：Cmd+C）複製
  4. 回到這個頁面，貼進掃描框

⚠️ 用 v0.dev、Next.js 這類工具做的網站，原始碼可能是打包壓縮過的，能抓到的問題會變少，建議改用方法三。

方法三專案放在 GitHub 上
  1. 打開 GitHub 專案，點進想檢查的檔案（例如 index.html、app.js、API 路由檔）
  2. 按右上角的「Copy raw file」複製圖示
  3. 回到這個頁面貼上；多個檔案可用「多檔案模式」分開貼
