這個工具查得到什麼、查不到什麼

使用前先看這頁，避免對結果有錯誤期待。「工具沒標記」不代表「沒問題」。

查得到
  • 已知格式的明文 API 金鑰（OpenAI／Anthropic／Gemini／AWS／LINE），並分辨 Firebase 設定這類「本來就可公開」的值
  • Supabase／JWT 金鑰，區分 anon（可公開）與 service_role（絕不可公開）
  • 密碼用 MD5／SHA1 這類容易被破解的方式儲存
  • 網頁或框架設定檔是否設定 Content Security Policy
  • SQL Injection（字串拼接、模板插值、f-string、Python % 格式化）
  • 把文字當程式執行（eval、exec、pickle、yaml.load）
  • 疑似缺少擁有權檢查（登入的人看得到別人的資料），含 Express 路由寫法
  • 多檔案：同一敏感欄位在不同檔案的遮罩不一致、路由缺少流量限制
做不到／僅供參考
  • 字串拆開再組合的金鑰
  • 需要實際執行才能確認的邏輯漏洞、協定層級漏洞
  • 打包壓縮過的程式碼：金鑰檢查仍有效，權限、SQL 這類邏輯檢查幾乎無法判斷
  • 權限檢查只是模式比對，主要針對 JavaScript／Express，一定會有漏判與誤判
  • 疑似自訂密鑰、內部網址、環境變數明文備用值 — 沒有固定格式，誤判率較高
  • 後端、資料庫權限規則（RLS／Security Rules）與雲端 IAM 設定
  • 私人 GitHub 專案（請下載後用拖放或開啟檔案）

「請你確認」的意思只是「這裡看起來可疑」，需要你自行對照程式邏輯確認，不是漏洞確診。規則主要針對 JavaScript／TypeScript／Python 常見寫法設計，其他語言涵蓋有限。

隱私：你的程式碼去了哪裡？

  • 哪裡都沒去。檢查完全在你的瀏覽器裡進行，程式碼只存在這個分頁的記憶體，關掉就消失。
  • 頁面本身被禁止在背景外傳。本頁設定了 Content Security Policy（內容安全政策），瀏覽器會擋下頁面在背景連到其他網站——載入外部資源、傳送資料都不行。這是瀏覽器強制執行的，不是只靠我們的承諾。
  • 唯一的例外：你按下「從 GitHub 匯入」時，頁面會向 api.github.com 與 raw.githubusercontent.com 讀取公開專案的檔案，不會送出任何內容。
  • 沒有追蹤、沒有外部字型或 CDN。所有檔案（含字型與語法分析函式庫）都放在本站。頁面上唯一會離開本站的方式，是你自己點的連結（例如頁尾的 GitHub 專案頁面）。
想自己確認？（約 1 分鐘）
  1. 在這個頁面按 F12（Mac：Cmd+Option+I）打開開發人員工具，切到「Network／網路」分頁。
  2. 回到「開始檢查」，按「看範例」（會自動檢查）。
  3. Network 分頁不會出現任何新的請求。你也可以先把網路斷線再檢查，結果完全一樣。

怎麼拿到「要檢查的程式碼」

依你的情況選一種。越上面的方法，檢查結果越完整。

最推薦專案有同步到 GitHub（Lovable、Bolt、v0 都可以設定）
  1. 打開你的 GitHub 專案頁面，複製網址列的網址（像 https://github.com/帳號/專案名稱）
  2. 貼到「開始檢查」頁最上面的 GitHub 欄位，按「匯入」，工具會自動抓檔案並檢查
  3. 如果專案是私人的，請用下面的方法二
方法二檔案在你的電腦上
  1. 把檔案直接拖進程式碼框，或按「開啟檔案」
  2. 一次選好幾個檔案時，工具會自動切換成多檔案模式
方法三只有已上線的網址
  1. 打開你的網站，在空白處按右鍵 →「檢視網頁原始碼」（或在網址前加 view-source:）
  2. 按 Ctrl+A 全選、Ctrl+C 複製（Mac 用 Cmd），貼進程式碼框

這種方式拿到的常是打包壓縮過的程式碼：金鑰外洩的檢查仍然有效，但權限、SQL 這類邏輯檢查幾乎無法判斷。工具會自動提醒你。為什麼不能直接輸入網址？因為瀏覽器禁止網頁讀取別的網站，要繞過就得把你的網址送到我們的伺服器，這會違反「內容不外送」的原則。
