這個工具查得到什麼、查不到什麼

使用前先看這頁，避免對掃描結果有錯誤期待。「工具沒標記」不代表「沒問題」。

可以，且相對可靠
  • 已知格式的明文 API 金鑰（OpenAI／Anthropic／Gemini／Firebase／Line／AWS）
  • HTML 頁面是否設定 Content Security Policy（含 Next.js／Nuxt 等框架設定檔的初步比對）
  • 密碼是否用 MD5／SHA1 這類不適合存密碼的雜湊函式
  • Supabase／JWT 格式金鑰，並區分 anon（可公開）與 service_role（絕不可公開）兩種風險等級
做不到 / 僅供保守提示
  • 字串拆分組合而成的金鑰
  • 協定層級漏洞、需動態執行才能確認的邏輯漏洞
  • 疑似缺少擁有權驗證（IDOR）— 只是模式比對，主要針對 JavaScript／Express 語法，不保證抓到、也一定會有誤判
  • 疑似自訂密鑰／權杖變數含明文字串、疑似內部服務端點 URL 寫死、環境變數讀取帶明文 fallback — 沒有固定格式可比對，僅按變數命名與字串特徵猜測，誤判率高於已知金鑰格式
  • .env 格式內容需直接貼上該檔案文字才會被掃描到，本工具不會、也無法自動讀取你的檔案系統
  • 後端是否真的驗證了前端送出的密鑰／權杖 — 這屬於後端邏輯，本工具只看得到你貼上的這份程式碼

「工具沒標記」不代表「沒問題」。第二層的「建議人工複查」結果，意義只是「這裡看起來可疑」，需要自行對照程式邏輯確認，不是漏洞確診。第二層規則主要針對 JavaScript／TypeScript／Python 常見寫法設計，對其他語言的涵蓋有限，掃描後會依貼上內容的語言特徵動態提示。

怎麼拿到「要貼進去的內容」

這個工具沒辦法直接輸入網址幫你檢查，需要你自己複製內容貼進掃描框。

這個工具沒辦法直接輸入網址幫你檢查——瀏覽器的安全機制不允許網頁擅自讀取別人網站的內容，就算是你自己的網站也一樣會被擋下來。你需要先自己把內容複製出來，貼進上面的框裡。以下兩種方法任選一種：

方法一你的網站是直接用網頁做的（沒有用 GitHub 管理）
  1. 打開你想檢查的網頁
  2. 在頁面空白處按滑鼠右鍵，選擇「檢視網頁原始碼」（英文版通常寫 View Page Source）；找不到的話也可以直接在網址列前面加上 view-source: 再打開
  3. 整頁會變成一大片文字，按 Ctrl+A（Mac 是 Cmd+A）全選，再按 Ctrl+C（Mac 是 Cmd+C）複製
  4. 回到這個頁面，貼進上面的框裡

⚠️ 如果你的網站是用 v0.dev、Next.js 這類工具做的，「檢視網頁原始碼」看到的內容可能是打包壓縮過的程式碼，跟開發時寫的原始檔案長得不一樣，工具能抓到的問題會變少。這種情況建議改用方法二。

方法二你的專案有放在 GitHub 上
  1. 打開你的 GitHub 專案頁面，找到你想檢查的檔案（例如 index.html、app.js，或任何看起來會有程式邏輯的檔案）
  2. 點進那個檔案，畫面右上角通常有一個「Copy raw content」或看起來像複製圖示的按鈕，點下去就會複製整份檔案內容
  3. 找不到那個按鈕的話，也可以直接把檔案裡的內容整段選取（點進檔案內容區域按 Ctrl+A / Cmd+A）再複製
  4. 回到這個頁面，貼進上面的框裡；如果你想檢查好幾個檔案，可以一個一個分開貼上分別掃描，或者接著貼在同一段後面一起掃
