# 真人測試包：三分鐘看不看得懂？

目的：驗證 Claude 無法驗證的三件事——**三分鐘內能不能自己完成檢查、看完結果會不會慌、敢不敢把程式碼貼進來**。
自動測試只能證明「功能正常」，這份測試證明「人用得懂」。

---

## 一、準備（約 15 分鐘）

| 項目 | 說明 |
|---|---|
| 受測者 | 3～5 位**不寫程式**的人（家人、同事、行銷／營運夥伴）。至少 1 位用手機測 |
| 裝置 | 他們自己的電腦或手機，打開 https://kenyuiyui.github.io/AI-website-sercurity-testing/ |
| 測試素材 | 把下面「素材 A」存成 `我的網站.js`，傳給受測者（LINE、Email 都可） |
| 你的角色 | 主持人兼觀察者：計時、記錄，**不解說、不幫忙** |
| 工具 | 這份文件印出來，或開一份空白表格照「三、觀察紀錄表」填 |

### 素材 A：模擬一份 AI 產生的網站程式碼（金鑰都是假的）

```js
import { createClient } from "@supabase/supabase-js";

const OPENAI_API_KEY = "sk-proj-TESTONLYabcdefghijklmnopqrstuvwxyz123456";

const firebaseConfig = {
  apiKey: "AIzaSyTESTONLY0000000000000000000000000",
  authDomain: "my-shop.firebaseapp.com",
  projectId: "my-shop"
};

export async function getOrder(orderId) {
  const result = await db.orders.findOne(orderId);
  return result;
}
```

預期結果（給你對照，不要給受測者看）：
「需要處理」1 件（OpenAI 金鑰）、「請你確認」2 件（Firebase 設定、權限檢查）。

## 二、任務腳本（每人約 10 分鐘）

開場時照念，之後就不要再說明：

> 「這是一個檢查網站程式碼安全的小工具。我想知道它好不好用，所以我們測的是工具，不是你。
> 做的時候請把你在想什麼說出來，例如『我在找…』『這個看不懂』。我不會回答問題，你就照你覺得對的方式做。」

| # | 念給受測者聽的任務 | 成功標準 | 時間上限 |
|---|---|---|---|
| 1 | 「你朋友傳了一個 `我的網站.js` 給你，請用這個網站檢查它。」 | 自己把內容放進去（拖放、開啟檔案或複製貼上皆可）並看到結果 | 3 分鐘 |
| 2 | 「用一句話告訴我：這個網站有沒有問題？最該先做什麼？」 | 說出「有金鑰外洩，要去後台換掉／撤銷」或意思相近 | 2 分鐘 |
| 3 | 「你要請工程師朋友幫忙修，把結果傳給他。」 | 找到「匯出報告」並複製或下載 | 2 分鐘 |
| 4 | 「如果這是你公司的真實程式碼，你敢貼進來嗎？為什麼？」 | 記錄回答；追問「怎樣你才會放心？」 | — |
| 5（選做） | 「如果你的專案放在 GitHub 上，你會怎麼檢查？」 | 看到並理解 GitHub 匯入欄位 | 1 分鐘 |

**超過時間上限就記為失敗**，直接進下一題，不要教。

### 結束後問 3 個問題

1. 看到結果的當下，你的感覺是？（很慌／有點擔心／還好／不在意）
2. 哪個地方最讓你困惑？
3. 你會推薦給用 AI 做網站的朋友嗎？為什麼？
